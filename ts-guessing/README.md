# TS-Guessing Replication Guide — Behavioral Contamination (Model-Level)

This folder documents and reproduces the **behavioral contamination** analysis presented in  
**“Benchmark Data Contamination in Underrepresented Languages: A Comprehensive Analysis Using Brazilian Data”** (Anonymous submission, 2025).

The analysis detects when models recall benchmark content rather than reasoning about it, using the **TS-Guessing** protocol integrated into a forked version of the [HELM framework (Stanford)](https://crfm.stanford.edu/helm/).

---

## 🎯 Objective

The TS-Guessing module measures **benchmark data contamination (BCD)** by testing whether a model can recall masked benchmark content.  
It provides a standardized, black-box method to assess potential memorization in **open and closed LLMs** without requiring access to their training data.

The forked HELM version used here integrates TS-Guessing directly into its evaluation pipeline, allowing **joint computation of performance metrics and contamination indicators** in a single run.

🔗 **Fork link:** [HELM-fork](https://anonymous.4open.science/r/helm-guessing-2EEC)

---

## ⚙️ Method Overview

Two contamination strategies are implemented:

1. **TS-Guessing Question Base**  
   Masks a random token in a benchmark question and prompts the model to recover it.

2. **TS-Guessing Question Multichoice**  
   For multiple-choice benchmarks: one *incorrect alternative* is masked, and the model is asked to reconstruct its text.  
   This is the strategy used in our replication experiments.

Each method supports three prompt languages:  
**pt** (Portuguese), **en** (English), and **zh** (Chinese).

## 🚀 Running the Analysis

To reproduce behavioral contamination measurements:

1. **Install and configure HELM (forked version)**  
   ```bash
   git clone [helm-fork]
   cd helm
   pip install -e .
   ````

2. **Run the evaluation with contamination analysis enabled**

   ```bash
   helm-run --run-entries enem_challenge:model=google/gemma-2-9b \
       --contamination ts_guessing_question_multichoice:pt \
       --suite my-suite -m 1500
   ```

3. **Summarize and visualize results**

   ```bash
   helm-summarize
   helm-server
   ```

   To verify our results, simply replace your generated `benchmark_output/` folder with the one provided in this repository and re-run `helm-summarize` and `helm-server`.

## 🧠 How It Works

The TS-Guessing protocol follows the functional methodology from
[Deng et al. (2024)](https://aclanthology.org/2024.naacl-long.482/):

* For each benchmark instance, a random *incorrect option* is masked.
* The model is prompted to reconstruct the masked text.
* The output is compared to the original option using:

  * **Exact Match (EM)** — binary measure of verbatim recall.
  * **ROUGE-L F1** — continuous measure of lexical overlap.
* Scores are aggregated to compute contamination indicators across benchmarks.

## 🧱 Implementation Details

The integration adds a new module to `src/helm/contamination/` and a new parameter to the HELM CLI:

```
--contamination technique_name:prompt_language
```

### Available techniques:

* `ts_guessing_question_base`
* `ts_guessing_question_multichoice`

### Example:

```bash
helm-run --run-entries enem_challenge:model=google/gemma-2-9b \
    --contamination ts_guessing_question_multichoice:pt \
    --suite my-suite -m 1500
```

### Key modified files:

* `run.py` — added support for the `--contamination` parameter.
* `runner.py` — integrates contamination results into HELM’s output.
* `contamination_evaluator.py` — manages the selection of contamination strategy.
* `ts_guessing_question_multichoice.py` — main implementation for multiple-choice tasks.
* `prompt_translations.py` — stores multilingual prompt templates.
* `utils_contamination.py` — utility functions for current and future extensions.
